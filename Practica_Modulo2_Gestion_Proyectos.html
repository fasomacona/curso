Práctica Completa — Módulo 2

Gestión de Proyectos de Ciencia de Datos

Duración estimada: 4 – 5 horas | Individual o en equipos de 2–3 personas

Objetivo de la Práctica

Aplicar de forma práctica los conceptos de gestión de proyectos de ciencia de datos: CRISP-DM, definición de roles, control de versiones con Git/GitHub y documentación profesional.

Al finalizar esta práctica habrás creado la base de un proyecto real listo para continuar en los siguientes módulos.

Caso de Estudio

Empresa: “RetailMax” (cadena de supermercados mediana).
Problema de negocio: La empresa tiene dificultades para predecir la demanda de productos frescos (frutas, verduras y lácteos). Esto genera:

  • Exceso de inventario → merma y pérdidas económicas
  • Falta de stock → clientes insatisfechos y pérdida de ventas

Objetivo del proyecto: Desarrollar un sistema de pronóstico de demanda semanal para 3 categorías de productos frescos, que permita optimizar los pedidos a proveedores.

Nota: No necesitas tener los datos reales todavía. En esta práctica trabajamos la parte de gestión y estructura del proyecto.

Actividad 1 Business Understanding (CRISP-DM) 45–60 min

Instrucciones: Completa el siguiente documento de entendimiento del negocio.

1.1 Definición del problema

  • ¿Cuál es el problema de negocio en una frase?
  • ¿Qué impacto económico tiene actualmente? (estimado)
  • ¿Quiénes son los principales stakeholders?
  • ¿Qué decisión de negocio se tomará con los resultados del proyecto?

1.2 Objetivos y criterios de éxito

Tipo Objetivo / Criterio
Objetivo de negocio Reducir la merma de productos frescos en al menos un 15% en 6 meses
Objetivo técnico Modelo de pronóstico con MAPE < 12% a nivel semanal
Criterio de aceptación El equipo de compras pueda usar el pronóstico en su proceso semanal

Tu tarea: Redacta en un archivo Markdown o documento:

  • Problema de negocio (claro y conciso)
  • 2–3 preguntas de negocio que el proyecto debe responder
  • Métricas de éxito (negocio + técnicas)
  • Restricciones conocidas (tiempo, datos, recursos)

Actividad 2 Roles y Responsabilidades 30 min

Asigna los siguientes roles al proyecto de RetailMax (puedes inventar nombres):

Rol Responsabilidades principales Persona asignada
Product Owner / Stakeholder de negocio Define prioridades y valida valor de negocio
Data Scientist Modelado, evaluación y experimentos
Data Analyst / EDA Exploración, limpieza y visualizaciones
Data Engineer (si aplica) Pipelines de datos y calidad
Project Lead / Scrum Master Facilita el proceso y elimina impedimentos

Entregable: Tabla de roles completada + descripción breve de cómo se comunicarán entre sí.

Actividad 3 Estructura del Repositorio + Git/GitHub 60–75 min Obligatoria

Objetivo: Crear la estructura profesional de un proyecto de ciencia de datos y subirla a GitHub.

3.1 Estructura de carpetas recomendada

retailmax-demanda/
├── data/
│   ├── raw/              # Datos originales (no modificar)
│   ├── processed/        # Datos limpios listos para modelar
│   └── external/         # Datos de fuentes externas
├── notebooks/
│   ├── 01_business_understanding.ipynb
│   ├── 02_eda.ipynb
│   ├── 03_modeling.ipynb
│   └── 04_evaluation.ipynb
├── src/                  # Código reutilizable (.py)
│   ├── data_processing.py
│   └── utils.py
├── reports/              # Reportes y presentaciones
├── figures/              # Gráficos exportados
├── .gitignore
├── README.md
├── requirements.txt
└── environment.yml

3.2 Pasos a seguir

  1. Crea la carpeta del proyecto en tu computadora con la estructura anterior.
  2. Crea un archivo .gitignore (incluye al menos: __pycache__/, .ipynb_checkpoints/, data/raw/, .env).
  3. Crea un README.md profesional (ver plantilla abajo).
  4. Crea un requirements.txt básico.
  5. Inicializa Git y súbelo a un repositorio nuevo en GitHub.

Actividad 4 Planificación de Sprints (Agile) 40 min

Define un plan de 3 sprints (de 1 semana cada uno) para el proyecto:

Sprint Objetivo principal Entregables Duración
Sprint 1 Business Understanding + Data Understanding Documento de negocio + EDA inicial 1 semana
Sprint 2 Data Preparation + Primeros modelos Datos limpios + baseline model 1 semana
Sprint 3 Mejora de modelos + Evaluación + Entrega Modelo final + reporte + presentación 1 semana

Tu tarea: Adapta o completa la tabla anterior según tu visión del proyecto y define 3–5 tareas concretas del backlog del Sprint 1.

Actividad 5 Definición de “Done” 20 min

Define cuándo se considera terminada cada fase importante:

  • Una tarea de limpieza de datos se considera “Done” cuando…
  • Un notebook de EDA se considera “Done” cuando…
  • Un modelo se considera “Done” cuando…
  • El proyecto completo se considera “Done” cuando…

Criterios de Evaluación de esta Práctica

Criterio Peso

Consejos para tener éxito

  • Sé concreto y realista en los objetivos de negocio.
  • El README es la “carta de presentación” de tu proyecto: cuídalo.
  • Usa commits claros y frecuentes.
  • Piensa siempre en quién va a leer tu documentación (stakeholders no técnicos).
  • Esta estructura te servirá para el Proyecto Final del Módulo 5.
